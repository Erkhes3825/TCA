# Tsutaeru（モック）— Web アプリ版

外国人患者が自分のスマホで症状を話すと、日本語の問診票になって医療者に渡る——という Web アプリの**ピッチ用モック**です。
音声認識・翻訳はまだ入っていません。サンプルの会話を台本どおりに再生しています。

このフォルダをそのまま GitHub のリポジトリにすれば、**GitHub Pages で公開できます**。
`docs/` にビルド済みのファイルが入っているので、**Node.js のインストールも GitHub Actions も要りません**。

## 音声認識（Azure AI Speech）をつなぐ

`config.json` の `speechTokenUrl` に Azure Functions の URL を入れると、マイクを押したときに本物の音声認識が動きます（空ならデモのまま）。
Azure 側の作り方は [`api/README.md`](api/README.md)。この機能を入れたあとの `docs/` は、`npm install` → `npm run build` で作り直す必要があります。

## 1. まず手元で見てみる（インストール不要）

`docs/index.html` をダブルクリックして、ブラウザで開いてください。ネットにつながっていなくても動きます。

- 画面の切り替え：URL の末尾を `#/`（患者のスマホ画面）、`#/compare`（汎用翻訳との違い）、`#/clinician`（医療者向けの問診票）にする
- パソコンで開くとスマホの枠つきで表示されます

## 2. GitHub で公開する（いちばん簡単な方法）

コマンドは使いません。ブラウザだけでできます。

1. GitHub で新しいリポジトリを作る（名前の例：`tsutaeru`）。README などの初期ファイルは付けなくてよい
2. リポジトリの画面で **Add file → Upload files** を押す
3. このフォルダの**中身**（`docs`・`src`・`public`・`scripts`・`speech-dict` の各フォルダと、`README.md`・`package.json` などのファイル）をまとめてドラッグ＆ドロップし、**Commit changes** を押す
   - フォルダごと（`tsutaeru-webapp` ごと）ではなく、中身を入れてください。`docs` がリポジトリの一番上に来るようにします
   - 一度にアップロードできるのは 100 ファイルまでです。このフォルダは約 60 ファイルなので 1 回で入ります
4. **Settings → Pages** を開く
5. **Build and deployment** の **Source** を「**Deploy from a branch**」にする
6. **Branch** を「`main`」、フォルダを「**`/docs`**」にして **Save**
7. 数分待つと、Pages の画面の上に URL（`https://ユーザー名.github.io/リポジトリ名/`）が出ます。スマホでも開けます

> Mac の Finder では、名前が `.` で始まるファイル（`.gitignore`）は見えないため、アップロードされないことがあります。公開には影響しません。

### スマホのホーム画面に追加する

公開した URL をスマホで開き、

- iPhone：Safari の共有ボタン →「ホーム画面に追加」
- Android：Chrome のメニュー →「ホーム画面に追加」または「アプリをインストール」

アプリのように全画面で開けます。**一度開いておけば、電波がない場所でも表示できます**（オフライン対応）。

## 3. 学校のアカウント（edu）で制限があったとき

学校の GitHub は、管理者の設定でできることが絞られていることがあります。よくある例と対処です。

| 起きること | 考えられる理由 | 対処 |
| --- | --- | --- |
| Settings に **Pages** が無い、または押せない | 学校の組織（Organization）が Pages を止めている | 先生や情報担当に「この組織で Pages を使えるか」聞く。個人アカウントのリポジトリで公開するのも手（学校のルールを確認してから） |
| Pages で「アップグレードが必要」と出る | **非公開（Private）リポジトリ**の Pages は、無料プランでは使えない | リポジトリを公開（Public）にする。学生は GitHub Education（Student Developer Pack）に申し込むと個人アカウントが GitHub Pro になり、非公開リポジトリでも Pages を使える |
| 公開（Public）リポジトリを作れない | 組織の設定で、公開リポジトリの作成が禁止されている | 非公開で作り、上の「アップグレード」の行を参照。無理なら管理者に相談 |
| GitHub Actions が使えない | 組織の設定で止められている | この手順は Actions を使わないので影響なし |
| ログインのたびに学校のサインイン画面が出る・2 段階認証を求められる | 学校のアカウント管理（SSO・2FA の必須化） | 学校の指示どおりに設定する |
| Git やソフトをパソコンに入れられない | 学校のパソコンの制限 | 上の「Upload files」の手順ならブラウザだけでできる |
| どうしても公開できない | — | `docs/index.html` 1 ファイルを共有ドライブやメールで渡せば、開いた人のパソコンで動く |

**注意：Pages の URL は誰でも開けます。** リポジトリを非公開にしても、Pages のサイト自体は基本的にインターネットに公開されます（一部の企業向けプランを除く）。**実在の患者の情報や個人情報は絶対に入れないでください。**

## 4. 中国・モンゴルでの現地テストについて

- **中国本土からは `github.io` につながらない、またはとても遅いことがあります。** 出発前に日本で URL を開き、「ホーム画面に追加」しておいてください。一度開いておけば、オフラインでも表示できます
- パソコンなら、`docs/index.html` を USB メモリなどで持っていけば、ネットなしで開けます
- 画面の文言とサンプル会話は 10 言語あります。そのうち**回答まで通しで見られるのは英語・中国語・ベトナム語**です。モンゴル語などは質問まで訳してあり、回答は英語のサンプルが出ます
- **英語以外の訳はすべて AI（Claude）が書いたもので、ネイティブの確認はまだです。** 現地の人に見せる前に、ネイティブに確認してもらってください

## 5. 中身を直したいとき（Node.js が必要）

文言や会話を変えるには、ソースを直してビルドし直します。

1. [Node.js](https://nodejs.org/) の LTS 版（20 以上）を入れる
2. このフォルダでターミナルを開き、次を順に実行

```bash
npm install
```

```bash
npm run dev
```

3. 表示された `http://localhost:5173` をブラウザで開く。ファイルを保存すると画面にすぐ反映されます
4. 直し終わったら次を実行すると、`docs/` が作り直されます

```bash
npm run build
```

5. 変わった `docs/` などを GitHub に上げ直す（Upload files で上書き、または git で push）。数分で公開ページに反映されます

パソコンに Node.js を入れられない場合は、GitHub の **Codespaces**（ブラウザで動く開発環境）でも同じことができます。ただし学校の設定で使えないこともあります。

### どこを直せばいいか

| 直したいもの | ファイル |
| --- | --- |
| 対応言語の一覧 | `src/data/languages.ts` |
| 患者画面のボタン・見出し・質問の文言（10 言語） | `src/data/ui.ts` |
| サンプルの会話（患者の回答） | `src/data/interview.ts` |
| 聞き足しの質問と回答 | `src/data/followUps.ts` |
| 医療者向け画面の内容 | `src/data/clinicianSheet.ts` |
| 色・文字の大きさ | `src/styles.css`（色は先頭の `:root` にまとまっています） |
| トップ画面のバージョン表記 | `package.json` の `version`（直して公開するたびに上げる） |

### デモ用の URL パラメータ（手元の `npm run dev` で使う）

- `?locale=en-GB#/` … 端末の言語設定を上書きして試す。`?locale=ja,ja-JP,en-JP#/` のように、カンマ区切りで言語リストも渡せる
- `?gloss=0#/` … 患者画面の日本語の補足（灰色の小さな字）を消す

## 6. 作るときに守ること（仕様上の線引き）

- **診断・病名の推定はしない。** 翻訳と問診の整理だけにする。病名の推定を入れると、医療機器のプログラムに当たるかどうかの検討が必要になる
- 医療者向け画面では、訳に必ず原文を並べる。口語・方言を医療用語に置き換えた箇所は黄色のタグで見せる
- 言語は端末の設定から推定するが、必ず本人に確認させる
- 「汎用翻訳との違い」画面（`src/data/compare.ts`）の「直訳の例」は説明用の作文。実在の翻訳サービスの出力として見せない
- 患者の話す内容は、要配慮個人情報（健康情報）にあたる。本当に音声認識や翻訳の API につなぐときは、保存するか・どこに送るか・同意をどう取るかを先に決める

## 7. フォルダの中身

| パス | 中身 |
| --- | --- |
| `docs/` | **公開用のビルド済みファイル**。`index.html` 1 枚にアプリ全体が入っている。ほかはホーム画面用のアイコン・設定と、オフライン用の `sw.js` |
| `src/` | ソースコード（React + TypeScript） |
| `public/` | アイコン・manifest・`sw.js` の元ファイル（ビルドで `docs/` にコピーされる） |
| `scripts/build-web.mjs` | `npm run build` の中身。1 枚の HTML にまとめて `docs/` に書き出す |
| `speech-dict/` | 音声認識用の医療用語辞書の叩き台（中国語・日本語、4 言語対照表）。説明は中の README |
| `package.json` ほか | ビルドの設定 |

技術：Vite + React 18 + TypeScript。外部のサーバーや API は使っていません（すべてブラウザの中で動きます）。
